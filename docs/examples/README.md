# Примеры входных данных

Материал для быстрой проверки ассистента руками (тем же сценарием, что и
живая регрессия `tests/goldens.jsonl`).

## 1. Подбор pdf по названию болезни (детерминированная проверка поиска)

Режим `pdf <название>` не вызывает модель-ответчик — только извлечение,
поиск и отбор. Ожидание — топ-1 выдачи содержит подстроку из второго
столбца (аббревиатуры должны расширяться сами):

| Запрос | В топ-1 ожидается |
|---|---|
| `pdf острый инфаркт миокарда с подъемом сегмента ST` | «инфаркт…» |
| `pdf ХСН` | «…недостаточн…» |
| `pdf хроническая обструктивная болезнь легких` | «…обструктивная болезнь легких» |
| `pdf сахарный диабет 2 типа` | «…диабет 2 типа» |
| `pdf фибрилляция предсердий` | «…фибрилляция…» |
| `pdf железодефицитная анемия` | «…железодефицитная…» |
| `pdf бронхиальная астма` | «…астма…» |
| `pdf ишемическая болезнь сердца` | «…ишемическая болезнь сердца» |
| `pdf ХБП` | «…болезнь почек…» |

## 2. Полные вопросы (весь конвейер: ответ + приложение с pdf)

| Вопрос | Что ожидать |
|---|---|
| «Какие критерии диагностики хронической сердечной недостаточности?» | ответ + ссылка на клинрек по ХСН |
| «Как диагностировать и лечить сахарный диабет 2 типа у взрослых?» | клинрек «Сахарный диабет 2 типа» (взрослый) |
| «Какие рекомендации по лечению внебольничной пневмонии у взрослых?» | клинрек по внебольничной пневмонии |
| «А просто при головной боли?» | **взрослая** версия «Головная боль напряжения» (не детская — проверка различения аудитории) |
| «Как оформить больничный лист пациенту?» | ответ без приложения pdf: болезни в ответе нет (`no_disease`) — ничего не прикладывать тоже правильно |
| «Что с одышкой?» + карта пациента | ответ с учётом карты; текст карты не попадает в историю/аудит |

Карта пациента: `data/patient_cards/*.амбулаторная_карта.md` — 5 вымышленных
демо-карт, например `Иванова_МП.амбулаторная_карта.md`. Приложить можно в UI
кнопкой «Карта пациента» или через API (см. ниже).

## 3. API-примеры (curl)

```bash
BASE=http://127.0.0.1:8866

# создать сессию
SID=$(curl -s -X POST $BASE/api/sessions | python -c "import sys,json;print(json.load(sys.stdin)['id'])")

# здоровье стека (3 эндпоинта, свежесть индекса, pdf-корпус)
curl -s $BASE/api/health

# список демо-карт пациентов
curl -s $BASE/api/cards

# приложить карту к сессии
curl -s -X POST $BASE/api/sessions/$SID/card \
     -H "Content-Type: application/json" \
     -d '{"file": "Иванова_МП.амбулаторная_карта.md"}'

# задать вопрос — SSE-поток: события ответа, статусов подбора pdf и приложения
curl -N -X POST $BASE/api/chat -H "Content-Type: application/json" \
     -d "{\"session_id\": \"$SID\", \"question\": \"Какие критерии диагностики ХСН?\"}"

# ручной подбор pdf (без модели-ответчика)
curl -N -X POST $BASE/api/chat -H "Content-Type: application/json" \
     -d "{\"session_id\": \"$SID\", \"question\": \"pdf ХСН\"}"

# статистика использования/ошибок/латентностей (то, что видно на /admin)
curl -s "$BASE/api/stats?days=7"

# пересмотреть вердикт отбора: 👎 = negate (переключить пару «приложено/отфильтровано»),
# 👍 = confirm (подтвердить один раз); текущее состояние — current: right|wrong
curl -s -X POST $BASE/api/verdicts -H "Content-Type: application/json" \
     -d '{"disease": "головная боль напряжения", "audience": "adult", "code_version": "162_3", "current": "right", "action": "negate"}'

# «· из кэша» в UI: забыть одну пару — следующая переоценит её живым отбором
curl -s -X POST $BASE/api/verdicts -H "Content-Type: application/json" \
     -d '{"disease": "головная боль напряжения", "audience": "adult", "code_version": "162_3", "action": "forget"}'
```

## 4. CLI-эквиваленты

```powershell
python -m medassistant ask --question "Какие критерии диагностики ХСН?" --save
python -m medassistant ask --question "pdf ХСН"
python -m medassistant ask --question "Что с одышкой?" --card Иванова_МП.амбулаторная_карта.md
python -m medassistant search --name "ХСН"     # отладка поиска: варианты + топ-5
```
